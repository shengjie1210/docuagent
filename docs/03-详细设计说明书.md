## 4. Service 层方法签名

### 4.1 AuthService

```java
public interface AuthService {
    LoginVO register(RegisterRequest req);
    LoginVO login(LoginRequest req);
}
```

**实现要点**：
- register：检查用户名是否重复（409），BCrypt 加密密码，存库，生成 token 返回
- login：按用户名查库，BCrypt 比对密码，失败抛 401，成功生成 token

### 4.2 DocumentService

```java
public interface DocumentService {
    DocumentVO upload(MultipartFile file, Long userId);
    PageResult<DocumentVO> list(String keyword, int page, int size, Long userId);
    DocumentVO getById(Long id, Long userId);
    String getContent(Long id, Long userId);
    void delete(Long id, Long userId);
}
```

**实现要点（upload 核心流程）**：
```
1. 校验文件类型（白名单 pdf/docx/md/txt），不通过抛 415
2. 校验大小 <= 20MB，不通过抛 413
3. 生成唯一文件名：UUID + 原扩展名
4. 存到 upload/ 目录
5. document 表插入一条记录，status=processing
6. 异步执行（或同步）：
   a. DocumentReader 读取文本内容
   b. TokenTextSplitter 切分（500 字符，重叠 50）
   c. EmbeddingModel 向量化
   d. VectorStore.add(向量 + 元数据 docId/userId/filename)
   e. ChatClient 生成摘要
   f. 更新 document 表：summary, chunk_count, status=ready
7. 返回 DocumentVO
```

### 4.3 RagService

```java
public interface RagService {
    /**
     * 检索与问题最相关的文档片段
     * @param question 用户问题
     * @param userId   当前用户（只搜自己的文档）
     * @return 检索结果列表，包含文本和元数据
     */
    List<DocumentFragment> retrieve(String question, Long userId);
}
```

**DocumentFragment**（内部 DTO）：
```java
@Data
@AllArgsConstructor
public class DocumentFragment {
    private String content;     // 片段文本
    private Long docId;
    private String filename;
}
```

**retrieve 实现要点**：
```
1. 问题向量化（EmbeddingModel.embed）
2. VectorStore.similaritySearch(SearchRequest.query(question).withTopK(5))
3. 过滤元数据：metadata.userId == 当前用户（数据隔离）
4. 返回 List<DocumentFragment>
5. 如果结果为空或最高分低于阈值（0.5），返回空列表
```

### 4.4 ChatService

```java
public interface ChatService {
    /**
     * 流式问答，结果通过 SseEmitter 推送
     */
    void chatStream(ChatRequest req, Long userId, SseEmitter emitter);
}
```

**chatStream 实现要点**：
```
1. 校验 conversationId 属于当前用户，否则抛 403
2. 把用户消息存入 message 表（role=user）
3. 调用 RagService.retrieve(question, userId) 拿相关片段
4. 取最近 10 轮对话历史（从 message 表查）
5. 构建 System Prompt：
   "你是文档助手。仅根据以下资料回答用户问题。
    如果资料中没有相关信息，明确说'未在您的文档中找到相关信息'。
    资料：
    {fragment1}
    {fragment2}
    ..."
6. 组装 messages：system + history + user
7. 调用 ChatClient
     .messages(messages)
     .tools(documentTools)       // 注册工具
     .stream()
8. 每收到一个 token，emitter.send(SSE event: chunk)
9. 流结束：
   a. 把完整回答存入 message 表（role=assistant, sources=JSON）
   b. emitter.send(SSE event: done, 带 sources)
   c. emitter.complete()
10. 异常时：emitter.send(SSE event: error)，emitter.completeWithError()
```

## 7. 关键流程伪代码

### 7.1 文档上传完整流程

```
function upload(file, userId):
    assert file.type in [pdf, docx, md, txt]  else throw 415
    assert file.size <= 20MB                   else throw 413

    savedName = UUID + "." + file.ext
    file.saveTo("upload/" + savedName)

    doc = Document(userId, filename, type, savedName, size, status="processing")
    documentMapper.insert(doc)

    try:
        text = readText(file)                    // PDF/Word 提取
        chunks = splitText(text, 500, 50)        // 切分

        for chunk in chunks:
            vector = embeddingModel.embed(chunk)
            vectorStore.add(vector, metadata={docId, userId, filename})

        summary = chatClient.prompt("总结这段文档: " + text).call()
        doc.summary = summary
        doc.chunkCount = chunks.size
        doc.status = "ready"
        documentMapper.update(doc)
    catch e:
        doc.status = "failed"
        documentMapper.update(doc)
        throw 503 "文档解析失败"
```

### 7.2 RAG 问答完整流程

```
function chatStream(req, userId, emitter):
    conv = conversationMapper.selectById(req.conversationId)
    assert conv.userId == userId              else throw 403

    saveMessage(conv.id, "user", req.message)

    fragments = ragService.retrieve(req.message, userId)

    if fragments.empty:
        systemPrompt = "资料为空，直接告诉用户未找到相关信息"
    else:
        systemPrompt = buildPrompt(fragments)

    history = messageMapper.selectRecent(conv.id, limit=10)

    emitter.onClose(() -> chatClient.stop())

    fullAnswer = ""
    chatClient
        .prompt(systemPrompt)
        .messages(history)
        .user(req.message)
        .stream()
        .content()
        .doOnNext(token -> {
            fullAnswer += token
            emitter.send({type: "chunk", content: token})
        })
        .doOnComplete(() -> {
            saveMessage(conv.id, "assistant", fullAnswer, sources=fragments)
            emitter.send({type: "done", sources: fragments})
            emitter.complete()
        })
        .subscribe()
```

## 10. AI 服务商动态配置（补充详细设计）

### 10.1 需求背景
V1 设计里把 DashScope 的 base-url、api-key、model 写死在 application.yml。
实际使用时，用户希望能在前端页面切换不同服务商（OpenAI / DashScope / Ollama / 本地模型），
不用改代码、不用重启服务。

### 10.2 数据库新增表

```sql
-- AI 服务商配置表（每个用户一套，V1 可全局共享一套默认）
CREATE TABLE ai_provider_config (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT COMMENT '哪个用户的配置，0 表示全局默认',
    provider    VARCHAR(50) NOT NULL COMMENT 'dashscope/openai/ollama',
    base_url    VARCHAR(500) NOT NULL,
    api_key     VARCHAR(500) COMMENT '加密存储',
    chat_model  VARCHAR(100) NOT NULL COMMENT 'qwen-plus/gpt-4o-mini/llama3',
    embed_model VARCHAR(100) COMMENT 'text-embedding-v3 / text-embedding-3-small',
    is_default  TINYINT DEFAULT 0 COMMENT '是否当前启用',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**核心设计：ChatModel 怎么动态构建**

不再用 Spring Boot 自动装配的单例 ChatModel，而是**每次请求时根据当前用户的配置现场构建**：

```java
public ChatModel getCurrentChatModel(Long userId) {
    AiProviderConfig config = getActiveConfig(userId);

    OpenAiChatModel model = OpenAiChatModel.builder()
            .baseUrl(config.getBaseUrl())
            .apiKey(config.getApiKey())
            .model(config.getChatModel())
            .build();

    return model;
}
```

**关键点**：
- 不用 `spring.ai.openai.*` 配置，那些只作为"系统默认"兜底
- 真正的运行时配置从数据库读
- 用户切换默认服务商 -> 下次对话自动用新模型，不用重启

### 10.6 安全性考虑

- **api_key 加密存储**：数据库里不明文存，用 AES 对称加密（密钥从环境变量读）
- **测试连接**：不入库，临时用传入的配置调一次
- **删除默认配置**：禁止删除，如果只剩一个配置，提示"至少保留一个"
- **跨用户隔离**：只能看自己的配置，管理员（V1 不做）可以看全局

```java
ChatModel chatModel = aiProviderConfigService.getCurrentChatModel(userId);
ChatClient chatClient = ChatClient.builder(chatModel).build();
chatClient.prompt(...)
```

**代价**：每次请求构建一次 ChatClient 对象，有轻微开销，但换来"用户可切换模型"的灵活性，值得。
（优化：可以按 userId + provider 做本地缓存，配置不变就复用）

### 10.8 面试怎么讲这个设计

**Q：为什么要把服务商配置放数据库，不写 application.yml？**
> 写死配置意味着每次换模型都要改代码重启。实际企业里多租户场景下，每个用户/租户用不同模型、不同 Key 是常态。我把配置存数据库，前端可视化管理，运行时动态构建 ChatModel，切换服务商不用重启。

**Q：api_key 怎么存的？**
> 不能明文存数据库。用 AES 对称加密，密钥从环境变量读。返回前端时也只显示前 4 位 + ****。

**Q：怎么测试配置能不能用？**
> 提供"测试连接"接口，拿用户填的配置现场发一个最小请求（比如"hi"），200 就返回成功，超时/401/404 把错误信息返回给前端。

**Q：切换模型后正在进行的对话怎么办？**
> 正在流式输出的请求不受影响（已经在跑了），下一条新消息才用新模型。这符合用户预期。

## 11. Ollama 本地模型接入（补充）

### 11.1 为什么 Ollama 容易接

Ollama 启动后默认监听 `http://localhost:11434`，并且**自带 OpenAI 兼容接口**：
- Chat 接口：`http://localhost:11434/v1/chat/completions`
- Embedding 接口：`http://localhost:11434/v1/embeddings`
- 不需要 api_key（随便填一个 "ollama" 即可）

也就是说，上一章的"动态配置服务商"机制**天然支持 Ollama**，只需要：
- base_url 填 `http://localhost:11434/v1`
- api_key 填任意值（比如 `ollama`）
- chat_model 填你本地已经下载的模型名（如 `qwen2.5:7b`、`llama3`）

### 11.2 可视化配置里怎么选

在"AI 设置"页新增服务商时，下拉选 **Ollama（本地）**，表单自动变化：

| 字段 | DashScope | OpenAI | Ollama |
|---|---|---|---|
| base_url | `https://dashscope...` | `https://api.openai.com` | `http://localhost:11434/v1`（自动填） |
| api_key | 必填 | 必填 | **隐藏**（不需要） |
| chat_model | 下拉 qwen-plus 等 | 下拉 gpt-4o 等 | **自动列出本地已下载的模型** |
| embed_model | text-embedding-v3 | text-embedding-3-small | nomic-embed-text 等 |

### 11.3 增强功能：自动发现本地模型

选 Ollama 时，前端可以调一个后端接口，**自动列出本机 Ollama 已下载的模型**：

**新增接口**：
```
GET /api/provider/ollama/models?baseUrl=http://localhost:11434
```

**后端实现**：
```java
public List<String> listOllamaModels(String baseUrl) {
    // 调 Ollama 原生接口：GET {baseUrl}/api/tags
    // 返回本地已下载的模型列表 ["qwen2.5:7b", "llama3", ...]
    // 失败（Ollama 没启动）返回空列表 + 提示"请先启动 Ollama"
}
```

**前端体验**：
- 选 Ollama -> chat_model 输入框变成下拉框
- 下拉自动从你的 Ollama 拉取已下载的模型
- 如果 Ollama 没启动，显示红字"未检测到 Ollama，请先启动"

### 11.4 Embedding 本地模型

Ollama 也能跑 embedding 模型（如 `nomic-embed-text`、`bge-m3`）：
- 装上后：`ollama pull nomic-embed-text`
- 配置时 embed_model 填 `nomic-embed-text`
- 这样**整个 RAG 流程可以完全离线**，不依赖任何云 API

这一点对面试很有价值：**你能讲清楚"全本地部署的 RAG 和云端 RAG 的区别、适用场景"**。

### 11.5 用户使用流程（可视化）

1. 用户在自己电脑装 Ollama（`https://ollama.com`）
2. 拉模型：`ollama pull qwen2.5:7b`、`ollama pull nomic-embed-text`
3. 打开 DocuAgent -> AI 设置 -> 新增服务商
4. 类型选 "Ollama"
5. base_url 自动填 `http://localhost:11434/v1`
6. chat_model 下拉选本地已下载的 qwen2.5:7b
7. embed_model 选 nomic-embed-text
8. 点【测试连接】-> 绿色成功
9. 点【设为默认】-> 以后所有对话走本地模型

### 11.6 多服务商切换场景举例

用户可以同时配三个：
- **DashScope 云端**：qwen-plus（平时用，效果好）
- **Ollama 本地**：qwen2.5:7b（没网/敏感文档时用）
- **OpenAI**：gpt-4o-mini（对比效果）

在设置页点一下"设为默认"就切换，对话不用重启。

### 11.7 面试怎么讲

**Q：Ollama 怎么接入的？和云端模型有什么区别？**
> Ollama 提供 OpenAI 兼容接口，所以我用同一套 ChatModel 构建逻辑，只换 base_url 和 model 名就行。区别是：云端模型效果好但要联网、要花钱、数据出域；本地 Ollama 免费、离线、数据不出本机，但效果受限于你下载的模型大小。我做了可视化切换，用户按场景选。

**Q：怎么知道用户本地有哪些模型？**
> Ollama 暴露了 `/api/tags` 接口，我后端代理转发一下，前端下拉自动列出。Ollama 没启动时给出友好提示。

**Q：Embedding 也能本地跑吗？**
> 可以，用 nomic-embed-text 或 bge-m3，整个 RAG 完全离线。适合处理敏感文档的场景。
