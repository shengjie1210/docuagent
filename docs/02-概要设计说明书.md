### 1.2 架构说明
- **前后端分离**：前端 Vue 3 通过 HTTP 调用后端 REST API，SSE 用于流式聊天
- **AI 能力层**：基于 Spring AI 的 ChatClient、VectorStore、ToolCallback 抽象，不直接耦合具体模型厂商
- **模型接入**：通过 OpenAI 兼容接口接入 DashScope（通义千问），后续可切换其他厂商
- **向量存储**：V1 使用 SimpleVectorStore，数据持久化到本地 JSON 文件，不引入独立向量数据库

### 1.3 关键技术选型

| 领域 | 选型 | 理由 |
|---|---|---|
| 语言版本 | JDK 21 (LTS) | 支持虚拟线程，Spring AI 新版本要求 |
| 框架 | Spring Boot 3.3.x | 主流稳定 |
| AI 框架 | Spring AI 1.0.x | 官方 ChatClient/VectorStore/Tool 抽象 |
| 模型接入 | OpenAI Compatible (DashScope) | 通义千问兼容 OpenAI 协议 |
| ORM | MyBatis + MyBatis-Plus | 熟悉，CRUD 效率高 |
| 数据库 | MySQL 8.x | 元数据存储 |
| 缓存 | Redis 7.x | 对话上下文缓存 |
| 向量库 | SimpleVectorStore | 轻量，免部署 |
| 前端 | Vue 3 + Vite + Element Plus | 熟悉 |
| 认证 | JJJWT (io.jsonwebtoken) | 无状态 |

### 2.2 建表 SQL

```sql
-- 用户表
CREATE TABLE user (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    username    VARCHAR(50) NOT NULL UNIQUE,
    password    VARCHAR(100) NOT NULL COMMENT 'BCrypt加密',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 文档表
CREATE TABLE document (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT NOT NULL,
    filename    VARCHAR(255) NOT NULL,
    file_type   VARCHAR(20) NOT NULL COMMENT 'pdf/docx/md/txt',
    file_path   VARCHAR(500) NOT NULL COMMENT '本地存储相对路径',
    size        BIGINT DEFAULT 0 COMMENT '字节数',
    summary     TEXT COMMENT 'AI生成的摘要',
    tags        VARCHAR(255) COMMENT '逗号分隔标签',
    chunk_count INT DEFAULT 0 COMMENT '切分块数',
    status      VARCHAR(20) DEFAULT 'processing' COMMENT 'processing/ready/failed',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user (user_id),
    INDEX idx_filename (filename)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 对话表
CREATE TABLE conversation (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT NOT NULL,
    title       VARCHAR(255) COMMENT '首条消息前20字',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 消息表
CREATE TABLE message (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    conversation_id BIGINT NOT NULL,
    role            VARCHAR(20) NOT NULL COMMENT 'user/assistant',
    content         TEXT NOT NULL,
    sources         TEXT COMMENT 'JSON数组：引用的文档片段',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_conv (conversation_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 3. API 接口设计

### 3.1 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 3.2 认证接口（无需 Token）

| 方法 | 路径 | 说明 | 入参 | 出参 |
|---|---|---|---|---|
| POST | `/api/auth/register` | 注册 | `{username, password}` | `{id, username}` |
| POST | `/api/auth/login` | 登录 | `{username, password}` | `{token, username}` |

### 3.3 文档接口（需 Token）

| 方法 | 路径 | 说明 | 入参 | 出参 |
|---|---|---|---|---|
| POST | `/api/document/upload` | 上传文档 | multipart/form-data: file | `{id, filename, status}` |
| GET | `/api/document/list` | 文档列表 | query: keyword?, page?, size? | `{total, records: [...]}` |
| GET | `/api/document/{id}` | 文档详情 | path: id | `{id, filename, summary, tags, ...}` |
| GET | `/api/document/{id}/content` | 文档原文 | path: id | `{content}` |
| DELETE | `/api/document/{id}` | 删除文档 | path: id | `success` |

### 3.4 对话接口（需 Token）

| 方法 | 路径 | 说明 | 入参 | 出参 |
|---|---|---|---|---|
| POST | `/api/conversation/create` | 新建对话 | `{title?}` | `{id, title}` |
| GET | `/api/conversation/list` | 对话列表 | 无 | `[{id, title, created_at}]` |
| DELETE | `/api/conversation/{id}` | 删除对话 | path: id | success |
| GET | `/api/conversation/{id}/messages` | 对话历史 | path: id | `[{role, content, sources}]` |
| POST | `/api/chat/stream` | SSE 流式问答 | `{conversationId, message}` | SSE 事件流 |

### 3.5 SSE 流式协议

**请求**：
```json
POST /api/chat/stream
{
  "conversationId": 1,
  "message": "这份文档的退货政策是什么？"
}
```

**SSE 事件流**：
```
event: message
data: {"type":"chunk","content":"根据"}

event: message
data: {"type":"chunk","content":"文档内容"}

event: done
data: {"type":"done","messageId":12,"sources":[{"docId":1,"filename":"退货政策.pdf","snippet":"..."}]}

event: error
data: {"type":"error","message":"未在文档中找到相关信息"}
```

## 5. 核心流程设计

### 5.1 文档上传 + 索引流程

```
用户上传文件
    │
    ▼
DocumentController.receive(file)
    │
    ▼
校验类型/大小 -> 存到 upload/ 目录
    │
    ▼
写入 document 表（status=processing）
    │
    ▼
DocumentReader 读取文本（PDF/TXT/MD）
    │
    ▼
TokenTextSplitter 切分（500字符，重叠50）
    │
    ▼
EmbeddingModel 向量化每块
    │
    ▼
VectorStore.add(embeddings)
    │
    ▼
调用 ChatClient 生成摘要
    │
    ▼
更新 document 表（status=ready, summary, chunk_count）
```

### 5.2 RAG 流式问答流程

```
用户提问（SSE 连接建立）
    │
    ▼
RagService.retrieve(question)
    │ 问题向量化
    ▼
VectorStore.similaritySearch(topK=5)
    │ 返回相关 chunks + 元数据(docId, filename)
    ▼
构建 Prompt：
  system: "基于以下资料回答，不知道就说不知道。资料：{chunks}"
  历史消息（最近10轮，从 Redis 取）
  user: question
    │
    ▼
ChatClient.stream(prompt)
    │ 逐 token 推送到 SSE
    ▼
流结束 -> 存 message 表（content + sources）
    │
    ▼
推送 done 事件（含引用来源）
```

### 5.3 Function Call 工具调用流程

```
用户: "帮我总结最近上传的文档"
    │
    ▼
ChatClient 带 ToolCallback 请求模型
    │
    ▼
模型返回 tool_call: list_recent_documents(limit=3)
    │
    ▼
Spring AI 自动反射调用 DocumentTools.listRecent(3)
    │ 返回文档列表 JSON
    ▼
结果喂回模型
    │
    ▼
模型再次返回 tool_call: summarize_document(docId=1)
    │
    ▼
调用 DocumentTools.summarize(1) -> 返回摘要
    ▼
结果喂回模型
    │
    ▼
模型不再要求调工具，生成自然语言回答
    │
    ▼
SSE 推送给前端
```

## 8. 工程规范（补充）

### 8.1 统一响应结构

所有 REST 接口返回统一 JSON：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "traceId": "a1b2c3d4"
}
```

**字段说明**：
| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 业务状态码，200 成功，4xx 客户端错误，5xx 服务端错误 |
| message | string | 提示信息，可直接展示给用户 |
| data | any | 业务数据，失败时为 null |
| traceId | string | 链路追踪 ID，排障用 |

**预定义业务码**：
| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录/Token 失效 |
| 403 | 无权限访问该资源 |
| 404 | 资源不存在 |
| 409 | 用户名已存在 |
| 500 | 服务器内部错误 |

### 8.2 统一异常处理

采用 Spring `@RestControllerAdvice` 全局异常捕获，避免每个 Controller 写 try-catch。

**异常体系**：
```
RuntimeException
  └── BusinessException（自定义业务异常）
        ├── 认证异常（401）
        ├── 权限异常（403）
        ├── 参数异常（400）
        └── 资源不存在异常（404）
```

**全局处理器**：
```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result handleBusiness(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldError().getDefaultMessage();
        return Result.error(400, msg);
    }

    @ExceptionHandler(Exception.class)
    public Result handleOther(Exception e) {
        log.error("未处理异常", e);
        return Result.error(500, "系统繁忙，请稍后重试");
    }
}
```

**效果**：
- Service 层直接 `throw new BusinessException(404, "文档不存在")`，不用管怎么返回
- 前端永远收到统一格式，不用处理各种五花八门的错误
- 异常栈只记日志，不暴露给前端

### 8.3 参数校验

- 使用 `spring-boot-starter-validation`
- DTO 字段加注解：`@NotBlank`、`@Email`、`@Size` 等
- 校验失败由全局异常处理器统一转成 400 + 中文提示

```java
public class LoginRequest {
    @NotBlank(message = "用户名不能为空")

    @NotBlank(message = "密码不能为空")
    @Size(min = 6, max = 30, message = "密码长度 6-30")
    private String password;
}
```

## 9. 统一响应格式（完整业务码表）

### 9.1 HTTP 状态码 vs 业务 code 的区别

很多新手搞混这两个，先讲清楚：

| 层级 | 谁定的 | 干什么用 | 本项目怎么用 |
|---|---|---|---|
| HTTP 状态码 | HTTP 协议 | 传输层结果：通没通、服务器在不在 | 永远返回 200，不管业务成不成功 |
| 业务 code | 项目自己定 | 业务层结果：登录成功还是密码错 | 前端根据这个判断弹什么提示 |

**为什么 HTTP 永远返回 200？**
- 前端 axios/fetch 看到 401/404/500 会直接进 catch 分支，拿不到后端的错误 message
- 我们把所有业务结果都包在 HTTP 200 里，用 body 里的 code 区分，前端 then 里统一处理，简单可靠

### 9.2 完整业务码表

| code | 含义 | HTTP | 前端处理建议 |
|---|---|---|---|
| **200** | 成功 | 200 | 正常使用 data |
| **400** | 请求参数错误（缺字段、格式不对） | 200 | message 直接弹提示 |
| **401** | 未登录或 Token 失效 | 200 | 清本地 token，跳登录页 |
| **403** | 已登录但无权访问该资源（比如看别人的文档） | 200 | message 弹"无权限" |
| **404** | 资源不存在（文档/对话被删了） | 200 | message 弹"资源不存在" |
| **409** | 冲突（用户名已存在） | 200 | message 弹"用户名已被注册" |
| **413** | 上传文件太大 | 200 | message 弹"文件不能超过 20MB" |
| **415** | 文件格式不支持 | 200 | message 弹"仅支持 PDF/Word/MD/TXT" |
| **429** | 请求太频繁（V1 预留，暂不实现） | 200 | 弹"操作太频繁，请稍后再试" |
| **500** | 服务器内部错误（空指针、DB 异常等） | 200 | 弹"系统繁忙，请稍后重试"，不暴露细节 |
| **503** | 大模型服务不可用（DashScope 挂了/Key 过期） | 200 | 弹"AI 服务暂不可用，请稍后再试" |

### 9.3 示例

**成功**：
```json
{ "code": 200, "message": "success", "data": { "id": 1, "filename": "test.pdf" }, "traceId": "abc123" }
```

**参数错误**：
```json
{ "code": 400, "message": "用户名不能为空", "data": null, "traceId": "def456" }
```

**未登录**：
```json
{ "code": 401, "message": "登录已过期，请重新登录", "data": null, "traceId": "ghi789" }
```

**文件太大**：
```json
{ "code": 413, "message": "文件大小不能超过 20MB", "data": null, "traceId": "jkl012" }
```

**AI 服务挂了**：
```json
{ "code": 503, "message": "AI 服务暂不可用，请稍后再试", "data": null, "traceId": "mno345" }
```

### 9.4 异常到 code 的映射

```
抛出异常                          -> 返回 code
─────────────────────────────────────────────
@Valid 校验失败                   -> 400
BusinessException(401, "...")     -> 401
BusinessException(403, "...")     -> 403
BusinessException(404, "...")     -> 404
BusinessException(409, "...")     -> 409
文件大小超限（Spring 抛）          -> 413
文件类型白名单校验失败             -> 415
DashScope 调用异常（catch）       -> 503
其他未捕获 Exception              -> 500
```
